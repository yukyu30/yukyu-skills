# ふりがな付きコード解説

貼られたコードの各行に、ふりがなのような注釈を添えて読み解く。読み手が「このコードの各部分が何をしているか」と「なぜ書くのか」を両方わかる状態にすることが目的。

## 進め方

1. **最初に一言で全体を説明する**
   例：「TypeScriptの『型の追記（モジュール拡張）』です。1行ずつ意味を添えて読みます。」

2. **意味のまとまりごとに見出しを立てる**
   見出しには、そのブロックが何をするかを書く（例：「前半：TanStack Router に自分のルーターを登録する」）。

3. **コードブロックの中で、各行の直後に `// ↑` で注釈をつける**
   - その行が何をしているかを平易な日本語で書く。
   - 型や式が入れ子になっているときは、部品ごとに分けて1行ずつ説明し、最後に `→` で結果をまとめる。

   ```ts
   href: NonNullable<ToOptions["to"]>;
   // ↑ React Aria の部品の href の型を決めます
   //   ToOptions["to"] … TanStack Router の to に書けるパスの型
   //   NonNullable<…>  … そこから undefined と null を除く
   //   → href には実在するルートのパスしか書けなくなる
   ```

   - 専門用語が出たら、カッコで名前を添える（例：「同じ名前の interface は自動で合体する。これを『宣言のマージ』と呼ぶ」）。

4. **ブロックごとに「何がうれしいか」を書く**
   仕組みだけでなく、書くと何が得られるかを1〜2文で書く。

5. **具体的な使用例を短く示す**
   そのコードがあると、実際にどう書けるようになるかを小さなコード例で見せる。例の中にも `↑` の注釈をつけてよい。

6. **まとめの表で締める**
   「部分 / 意味」の表で、全体を見渡せるようにする。

7. **大事な注意点を最後に1〜2文**
   例：「このコードは型のためだけのもので、実行時には何もしません。」のように、誤解しやすい点や別に必要な設定を書く。

## 書き方のルール

- 日本語で答える。
- 注釈は、その言語に詳しくない人にも通じる言葉で書く。ただし正確さは崩さない。
- コードを書き換えず、貼られたとおりに注釈だけ足す。
- 長い前置きや一般論は書かない。

## 続けての質問（「〇〇ってなに？」）への答え方

解説中に出てきたライブラリや概念について聞かれたら、次の形で短く答える。

1. **一言でいうと**：何かを1文で。
2. **特徴**：箇条書きで3〜4個。それぞれ太字の見出しと短い説明。
3. **種類や使い分け**：パッケージや方式が複数あれば表にする。
4. **さっきのコードとのつながり**：元のコードのどの部分に関係するかを書いて、元の話に戻す。
5. 必要なら、似た立ち位置のものを1行で挙げる。

バージョンや今の状況など、変わりうる事実を書くときは、調べて確かめてから書く。
